## Ephemeris and geometry

- **Application library:** Skyfield only. SpiceyPy is not an application dependency.
- **Calculation frame:** `MOON_ME_DE421`, using the NAIF lunar frame kernel and DE421 lunar orientation binary PCK. DE421 ME is the documented USGS lunar mapping standard.
- **Candidate coordinate source:** the cited peer-reviewed Artemis candidate-site study publishes exact DMS coordinates and hemispheres for three points: DM2/Nobile Rim 2 point 358, DM1/Amundsen Rim point 1121, and Site07/Peak Near Shackleton point 1223. It does **not** state a coordinate reference frame in its coordinate table or full text. The implementation explicitly interprets the published latitude/longitude as planetocentric coordinates in DE421 ME, following the USGS standard; this source-to-standard assignment is provisional and must be confirmed before making point-level absolute-location claims. The numerical coordinates themselves are source-published, not generated by this project. [1] [2]
- **Coordinate convention used by the engine:** planetocentric latitude; signed east-positive longitude in `[-180°, +180°]`. The source supplies S/E hemisphere labels; decimal values below are converted directly from the published DMS.
- **Sites:** DM2 point 358: `84°12′5.61″ S, 60°41′59.61″ E` = `(-84.201558333333°, +60.699891666667°)`. DM1 point 1121: `84°11′30.63″ S, 67°13′44.55″ E` = `(-84.191841666667°, +67.229041666667°)`. Site07 point 1223: `89°0′18.22″ S, 125°18′33.49″ E` = `(-89.005061111111°, +125.309302777778°)`. These are published points within candidate regions, not NASA-selected touchdown coordinates.
- **Surface model/elevation:** spherical lunar reference surface with `elevation_m=0.0` relative to the PCK-defined lunar radius. This is a calculation convention, not a claim about actual terrain elevation or a site-specific surveyed elevation.
- **Altitude convention:** geometric, vacuum, center-of-body topocentric direction at the same ephemeris epoch for observer and target; no light-time, stellar-aberration, or atmospheric-refraction correction. Sun/Earth results are center elevations, not disk visibility.
- **Time range:** supported dates are 2026-01-01 through 2049-12-31 UTC, within the DE421 and lunar-orientation files’ stated 1900–2050 coverage. Future UTC-to-TDB conversion uses Skyfield’s bundled time data; future leap seconds are inherently not predictable. The UI must not claim sub-second future timing accuracy.
- **Sampling:** one UTC sample per hour, with start and end dates inclusive as whole UTC days. Samples run from 00:00 UTC on the start date through 23:00 UTC on the end date. Maximum selected interval: 30 inclusive days; all selected sites use the same generated epochs. No interpolation is performed.
- **Output:** elevation and azimuth in degrees; geometric center elevation is positive above the local tangent horizon. Azimuth is clockwise from local north, normalized to `[0°, 360°)`.

## Limitations and remaining data gate

The result is smooth-horizon geometric center elevation. It does not include local terrain blockage, solar/Earth disk extent, atmospheric refraction, communications link budgets, relay architecture, power-system performance, or validated lunar dust physics. Earth elevation above zero is not a guarantee of a usable communications link; Sun-center elevation above zero is not a complete sunlight or power-generation assessment.

Before an unqualified location-accuracy claim, obtain confirmation that the candidate study’s published points are expressed in the DE421 ME planetocentric convention (or an authoritative source dataset that explicitly declares their datum and allows a documented transformation). The fixed-epoch reference tests validate the geometry implementation under the selected frame; they do not independently resolve this coordinate-provenance question.
